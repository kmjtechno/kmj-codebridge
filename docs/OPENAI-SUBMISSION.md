# OpenAI public directory release gate

This checklist tracks the current requirements for submitting KMJ CodeBridge as
a remote-MCP plugin. Source tests prove package shape; they do not prove review
approval or publication.

## Already implemented or observed

- Portable Agent Plugins manifest and canonical CodeBridge skill.
- Public HTTPS MCP resource at `https://kmjtechno.com/mcp`.
- OAuth protected-resource discovery and real account authorization observed in
  the current hosted integration path.
- Listing URLs for website, support, privacy policy, and terms.
- Primary/composer icons in the plugin package.
- Exactly five positive and three negative review cases in `plugin.json`.
- Commerce declaration and current canonical release notes in `plugin.json`.
- A configurable `/.well-known/openai-apps-challenge` response that serves
  only the exact portal-provided token and is disabled when no token is set.
- Credential scanning and package-contract tests in CI.

## Required before submission

- Complete KMJ TECHNO business verification in the OpenAI Platform
  organization used to submit the plugin.
- Ensure the submitting member has the required plugin/app management
  permissions.
- Deploy the final CodeBridge gateway build to the production MCP origin.
- Configure the exact domain-verification token generated by the submission
  portal, then complete **Verify Domain**.
- Run **Scan Tools** against the production MCP server and resolve every
  blocking finding, including tool annotation findings.
- Provision a dedicated reviewer account with sample devices/projects and no
  MFA, magic-link, email-code, SMS-code, or private-network dependency.
- Execute all five positive and three negative cases against that reviewer
  account on the supported ChatGPT/Codex surfaces.
- Record an accessible walkthrough video showing the main cases and tools and
  enter it as the review demo recording.
- Enter reviewer credentials only in the secure review form; never put them in
  this repository or plugin ZIP.
- Complete required policy attestations and submit the draft for review.
- After approval, an authorized owner must explicitly publish the approved
  plugin before it appears in the directory.

## Domain verification

The gateway accepts an optional private setting:

```json
{
  "openaiAppsChallenge": "PORTAL_TOKEN"
}
```

When configured, the allowed MCP host serves the exact value at:

```text
/.well-known/openai-apps-challenge
```

The response is plain text with `Cache-Control: no-store`. The token must come
from the OpenAI submission portal; do not invent, log, or commit a real token.

## Evidence discipline

Keep the production endpoint origin stable once the plugin is submitted. Treat
the MCP metadata scanned by the portal as a versioned public contract. Changes
to tool definitions, annotations, security metadata, or instructions should be
deployed deliberately and rescanned/reviewed as required.

A successful private/developer connection, green repository CI, or a generated
plugin ZIP is not the same as OpenAI review approval or public publication.
